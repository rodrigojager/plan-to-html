# CSS themes

Put a compatible CSS file in `SKILL_DIR/themes/`, then select it **before generation**:

```text
python SKILL_DIR/scripts/plan_html.py build PLAN.md --output work/plan.html --theme slate
python SKILL_DIR/scripts/plan_html.py build PLAN.md --output work/plan.html --theme path/to/downloaded.css
python SKILL_DIR/scripts/bundle_html.py work/plan.html --output plan.html
```

The bundled `default.css` is the full starting template; `slate.css` is a working example of a partial override. To add a theme, copy/download `NAME.css` into `themes/` and use `--theme NAME`. No Python or JavaScript changes, template rewriting, or AI conversion are required. The selected theme and its hash are recorded in the source manifest.

The original collection remains available: `papel`, `grafite`, `carbono`, `jade`, `prisma`, `caderno`, `coral`, `studio`, `iris`, and `polar`, in addition to `default` and `slate`.

Ten expressive themes extend that collection. Each is an independently usable CSS with light/dark palettes, deterministic materials and interaction states. No theme selector is generated by the skill.

## Contract

A plan-to-html theme declares **CSS custom properties** on `:root`, `html`, or those selectors with `data-theme` / `data-accent` attributes. It may include `@font-face`, `@media`, and `@supports`. The generator validates this contract before writing the output. Ordinary site CSS targeting arbitrary classes must be adapted to these variables; it is not automatically a compatible theme.

```css
:root {
  --bg: #f4f6fa;
  --surface: #ffffff;
  --surface-2: #eaf0f7;
  --text: #222e40;
  --muted: #56657a;
  --subtle: #66788e;
  --line: #d6e0ee;
  --accent: #315da5;
  --accent-soft: #e3edfd;
  --accent-strong: #224376;
  --code-bg: #edf2f9;
  --radius: 14px;
}
html[data-theme="dark"] {
  --bg: #121923;
  --surface: #192333;
  --surface-2: #202e41;
  --text: #e4ecf7;
  --muted: #b3c1d4;
  --subtle: #93a7c1;
  --line: #33455f;
  --accent: #a4c7ff;
  --accent-soft: #263c5f;
  --accent-strong: #cfe0ff;
  --code-bg: #141e2c;
}
```

Missing properties inherit the bundled default theme in the corresponding mode. Define matching light and dark values for any palette property you change. The switch changes `html[data-theme]`; theme selection does not add another runtime switch. `--accent` remains available for the bundled accent variants; theme files can provide their own `html[data-accent="blue"]` variants when needed.

The material/state hooks and reusable keyframes live in `assets/styles/skins.css`. For `--hover-animation` / `--selected-animation`, available names include `reader-laser` (background sweep), `reader-chalk` (brief sketch movement), and `reader-marker` (one-time marker reveal); supply normal CSS duration/easing/count, or `none`. No theme-specific JavaScript or Markdown substitution is involved. Keep decoration noninteractive and away from source text. Add a reusable hook to shared CSS if a future material needs one; use `--extra-css` / `--extra-js` for a one-off layout or behavior.

Use local font files referenced relative to the theme CSS. The final packager follows these references and embeds their bytes. Included families are Inter, JetBrains Mono, Source Serif 4, DM Sans, IBM Plex Sans, Caveat, Kalam, Cinzel, IM Fell English, Bebas Neue, Libre Baskerville, and Rajdhani, with licenses. No external font service is required. CSS/JS libraries distributed through CDNs may be downloaded locally and packaged when they work without a live service; a CDN origin alone is not a reason to discard an effect. Avoid `!important`; outer geometry and saved reading preferences belong to the reader.

## File organization

- `assets/reader.css`: ordered local imports; stable structural entry point.
- `assets/styles/fonts.css`: local font declarations.
- `assets/styles/tokens.css`: geometry, typography defaults, reading scale, duration.
- `assets/styles/base.css`, `layout.css`, `content.css`, `navigation.css`, `dialogs.css`: structural rules and Markdown presentation.
- `assets/styles/comfort.css`, `responsive.css`, `tools.css`: reading scale refinements, viewport adaptation, deterministic controls.
- `assets/styles/reading-map.css`, `assets/reading-map.js`: document-grid corridors, neighborhood isolation and collision-checked foreground connectors. Theme colors/radii apply without changing the map's structural geometry.
- `assets/styles/appearance.css`: stable typography, radius, surface, shadow, and texture hooks consumed by the theme variables.
- `assets/styles/skins.css`: shared material masks, document sheets, ornaments, hover/selected/pressed states and reusable decorative keyframes; appearance values remain in theme CSS.
- `assets/styles/motion.css`, `print.css`: motion preference and print behavior.
- `themes/*.css`: appearance variables; no control selectors or layout changes.
- `assets/reader.js`, `reader-tools.js`: behavior; no theme-specific branches.

Load order is structural CSS, default palette, selected palette, then optional `--extra-css`. The default palette supplies missing variables. For intentional layout changes or custom interactive additions, use `--extra-css` and `--extra-js` / `--extra-module`; preserve control selectors and accessible behavior. The independent packager consumes the final resource references, including any custom additions.

The same Markdown, skill version, selected theme, and enhancement specification produce the same HTML bytes. Another model/provider can choose optional additions differently; it does not generate or reinterpret the baseline CSS, markup conversion, or controls.
